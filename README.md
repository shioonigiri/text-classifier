# text-classifier

![tests](https://github.com/shioonigiri/text-classifier/actions/workflows/tests.yml/badge.svg)

メールやメモなどの文章から、**カテゴリ・期限・金額・必要な行動**を自動で抽出するツール。
設計の詳細は [docs/design.md](docs/design.md)、評価の詳細は [results/](results/) を参照。

## 背景と課題

就活や大学のメール・メモは数が多く、締切や必要な行動の見落としが起きやすい。
手作業の分類を自動化するだけでなく、「分類の精度を測り、改善する過程」までを
開発の成果物として残すことを目的に作っている。

## 出力形式

入力した文章に対して、次の形式で結果を返す。

```json
{
  "category": "選考・締切",
  "deadline": "2026-11-23",
  "amount": null,
  "action": "応募",
  "confidence": 0.67,
  "evidence": ["応募締切", "締切"]
}
```

カテゴリ: 選考・締切 / 就活案内 / 授業・課題 / 奨学金・手続き / セキュリティ・ログイン / 支払い・請求 / その他

## 使い方

```bash
python -m venv .venv
.venv/bin/pip install -r requirements.txt   # scikit-learn, pytest

.venv/bin/python -m src.classify           # サンプル文で分類を実行
.venv/bin/python -m src.evaluate           # v1 の精度評価 → results/ に保存
.venv/bin/python -m src.train              # v2 の学習と比較評価 → results/ に保存
.venv/bin/python -m pytest tests -q        # テスト（25件）
```

## 仕組み

### v1 ルールベース（現在採用中）
- 分類: カテゴリ別のキーワード辞書でスコアリング。同点時は「行動が必要なカテゴリ」を優先する固定順位で決定
- 期限抽出: 日付パターンを検出し、「締切・期限」の直後にある日付を優先。年がない日付は今年（過ぎていれば来年）に寄せる
- 金額抽出: 「12,000円」「¥3,500」「25万円」に対応（万円は円に換算）
- 行動抽出: 動詞パターンのうち、「ください・お願い」等の依頼表現が直後にあるものを優先

### v2 機械学習（実装・比較済み）
- 文字 n-gram の TF-IDF + ロジスティック回帰（日本語の分かち書きなしで動く構成）
- 評価は層化交差検証（学習に使っていないデータで予測）

## 評価結果

| バージョン | 方式 | 正解率 | 備考 |
|---|---|---:|---|
| v1 | ルールベース | 94.6%（53/56） | 合成データ56件で測定 |
| v2 | 機械学習 | 35.7% | 交差検証（学習に使わないデータで測定） |

詳細: [v1 結果](results/2026-10-26_v1-rules.md) / [v1・v2 比較](results/2026-10-26_v2-ml.md)

## 学び

- **少量データではルールベースが機械学習を大きく上回った。** 学習データが1カテゴリ6件程度では文字 n-gram が汎化せず、「MLを入れれば良くなるわけではない」ことを実測で確認した
- **誤分類の主因は汎用語の奪い合い。** 「申請」「手続き」は複数カテゴリに現れるため、単独では根拠が弱い。特徴の重み設計が精度を左右する
- **評価方法で数字の意味が変わる。** 辞書と相性の良い合成データでの94.6%と、交差検証での35.7%は、測り方が違う。数字は測定条件とセットで読む必要がある
- **適材適所がある。** 期限・金額の抽出はルールが強い領域、カテゴリ分類はデータが増えればMLが伸びる領域だと分かった

## 今後の課題

- 実メール（匿名化した抜粋）での評価と、学習データの拡充（数百件規模で v2 の再評価）
- 「来週金曜」などの相対日付への対応
- ルールとMLのハイブリッド（MLの確信度が低い場合はルールを優先）
- Gmail・メモ帳ドキュメントとの連携（情報整理の自動化への組み込み）

## ルール

- 実データ（メール本文など）はこのリポジトリに含めない。`data/private/` は .gitignore 対象
- リポジトリに置くのはコード・合成サンプル・評価結果のみ
- 外部送信・応募などの実行機能は持たせない（分類と抽出だけを行う）

## 構成

```
text-classifier/
  docs/design.md     … 設計書
  src/
    rules.py         … カテゴリ分類（キーワード辞書）
    extract.py       … 期限・金額・行動の抽出
    classify.py      … 分類の入口
    ml.py            … v2 機械学習モデル
    train.py         … v2 の学習と比較評価
    evaluate.py      … 精度評価（正解率・F1・混同行列）
  data/samples/      … 合成サンプル・評価データ
  tests/             … テスト25件
  results/           … 評価結果の履歴
```
